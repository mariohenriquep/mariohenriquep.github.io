O que fazWhat it does

Projetos e equipasProjects and teams

Quem cria um projeto fica Gestor e adiciona membros pelo email. Projetos terminados vão para o arquivo, só de leitura.

Whoever creates a project becomes its Manager and adds members by email. Finished projects move to a read-only archive.

TarefasTasks

Prioridade, prazo, estado, vários responsáveis e comentários. As tarefas atrasadas ficam assinaladas.

Priority, deadline, status, multiple assignees and comments. Overdue tasks are flagged.

Kanban

Quadro por projeto e quadro geral, com filtros guardados no endereço da página.

Per-project board and an overview board, with filters kept in the page URL.

Acesso seguroSecure access

JWT, passwords com bcrypt, bloqueio após tentativas falhadas, limites de pedidos e um registo que não revela que emails existem.

JWT, bcrypt-hashed passwords, lockout after failed attempts, rate limiting and a sign-up flow that doesn't reveal which emails exist.

Como foi feitaHow it was built

A Matriz foi desenvolvida de raiz na unidade curricular AI-Powered Software Engineering, em cinco fases, cada uma com entregáveis revistos antes de avançar:

Matriz was built from scratch for the AI-Powered Software Engineering course, in five phases, each with deliverables reviewed before moving on:

  1. Especificação: requisitos, user stories com critérios de aceitação e restrições.
  2. Arquitetura: monólito modular, modelo de dados e contrato REST em OpenAPI 3.1.
  3. Implementação: backend Spring Boot em clean architecture (regras verificadas com ArchUnit) e frontend React.
  4. Testes e revisões: plano de testes, testes com Testcontainers e Playwright, code review e security review.
  5. Entrega: imagens Docker, CI no GitHub Actions com Trivy e SonarQube Cloud, versões com tags e deploy no Render.
  1. Specification: requirements, user stories with acceptance criteria, and constraints.
  2. Architecture: modular monolith, data model and a REST contract in OpenAPI 3.1.
  3. Implementation: Spring Boot backend in clean architecture (rules enforced with ArchUnit) and a React frontend.
  4. Testing and reviews: test plan, tests with Testcontainers and Playwright, code review and security review.
  5. Delivery: Docker images, CI on GitHub Actions with Trivy and SonarQube Cloud, tagged releases and deployment on Render.

IA com revisão humana. Usei IA em todas as fases, como copiloto: prompts estruturados, um registo do uso em cada exercício e revisão humana de cada decisão, código e teste antes de entrar no projeto.

AI with human review. I used AI as a copilot in every phase: structured prompts, a log of its use for each exercise, and human review of every decision, piece of code and test before it went in.
